# 测试策略

本文件记录项目测试分层和最低要求。具体功能的验收标准写在对应 spec 中。

## 测试分层

| 层级 | 覆盖范围 | 何时必须补 | 备注 |
|------|----------|------------|------|
| 单元测试 | 纯业务逻辑、边界条件、错误分支 | 新增复杂逻辑 / 修复 bug | 与源文件对称目录 |
| 集成测试 | DB/MQ/缓存/外部依赖交互 | 核心链路、数据一致性、事务边界 | 关键依赖不 mock |
| 契约测试 | 对外 API、事件、回调 | 外部系统依赖本项目契约时 | 记录请求/响应样例 |
| 手工验证 | UI、联调、环境依赖强的流程 | 自动化成本过高时 | 必须记录步骤和结果 |

## 最低要求

- 修 bug:必须有复现路径;能自动化则补回归测试
- 新功能:至少覆盖主路径和一个失败/边界路径
- 数据变更:必须说明回滚方式或兼容策略
- 高风险模块:没有测试时必须在 spec 的风险段说明原因
