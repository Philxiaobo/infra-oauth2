description: 基于本项目规范进行代码审查,优先发现 bug、回归风险、测试缺口和规范未同步
---

用于提交前、功能完成后、或用户要求 review 时。按代码审查立场输出,问题优先,不要只总结。

## 执行步骤

1. **确定审查范围**
   - 查看 `git status --short`
   - 查看相关 diff
   - 读取本轮对应 spec 和 `AGENTS.md`

2. **按风险排序审查**
   - P0/P1 风险:资金、权限、数据迁移、对外契约、核心链路
   - 行为回归:兼容性、边界条件、并发、事务、幂等
   - 测试缺口:新增逻辑无测试、失败路径未覆盖、验证命令缺失
   - 规范同步:spec Tasks、AGENTS.md 实现状态、WORKLOG 是否同步

3. **输出 findings**
   - 先列问题,按严重度排序
   - 每个问题必须带文件和行号
   - 说明触发条件和影响
   - 没发现问题要明确说,并说明残余风险

## 输出格式

```markdown
## Findings

- [High] <问题标题> — `path/to/file:line`
  <为什么是问题,什么场景会出错,建议怎么修>

## Open Questions

- ...

## Test Gaps

- ...
```

## 注意

- 不要把风格建议放在 bug 前面
- 不要复述所有改动
- 无法判断业务语义时标注 open question
- 如果发现文档未同步,把它作为 review finding
