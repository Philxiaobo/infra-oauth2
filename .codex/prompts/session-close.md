description: 每次 Codex session 结束前的收尾流程:同步 spec、AGENTS.md、WORKLOG 和验证结果
---

用于每次准备结束当前 session 前。目标是把本轮上下文沉淀下来,避免下次重新摸索。

## 执行步骤

1. **汇总本轮事实**
   - 查看 `git status --short`
   - 查看本轮实际修改过的文件
   - 识别本轮对应的 spec、ADR、测试或验证命令

2. **同步 spec**
   - 如果本轮属于某个功能,读取对应 `specs/<feature>.spec.md`
   - 勾选已完成 Tasks,在任务行末尾标注关键代码位置
   - 未完成项保留为待办,必要时补充阻塞原因
   - 如果实现范围和原 spec 不一致,更新设计方案、风险或变更日志

3. **同步索引**
   - 更新 `specs/README.md` 中对应 spec 的状态、负责人、更新时间
   - 如果有新增/变更 ADR,更新 `docs/decisions/README.md`

4. **同步 AGENTS.md**
   - 只更新稳定的项目级事实和实现状态总览
   - 不把临时过程、长实现细节、调试记录塞进 AGENTS.md
   - 超过 200 行时,把详细约定拆到 `docs/conventions/*.md`

5. **追加 WORKLOG**
   - 在 `WORKLOG.md` 顶部追加绝对日期段落
   - 必须包含:目标、完成、进行中/未完成、下次继续、记录
   - 文件路径、类名、测试命令要写具体
   - 保持倒序,只保留最近 5 段;更旧内容归档到 `docs/worklog-archive/YYYY-MM.md`

6. **最终自检**
   - 本轮改动是否有对应 spec 或明确说明为什么没有
   - 已完成任务是否同步到 spec
   - 下一步是否能从 WORKLOG 顶部直接接上
   - 验证结果是否记录

## WORKLOG 段落模板

```markdown
## {{DATE}} (<session 主题>)

### 目标
- ...

### 完成
- <模块>: <一句话说明> (<文件路径> / <测试命令>)

### 进行中 / 未完成
- <卡住的地方>: <为什么没做完>

### 下次继续
- <具体下一步,带文件路径>

### 记录
- <临时发现、风险、待讨论>
```

## 注意

- 不要把没有实际验证过的内容写成"已验证"
- 不要因为时间不够跳过 WORKLOG;越是中断越要写
- 如果用户明确要求不改文档,最终说明要标注本轮没有做 session-close
